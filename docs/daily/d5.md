# D5 记忆抽取、冲突与流转

## 一句话理解
从多轮交互中**抽出**偏好/知识/工具/遗忘 4 类记忆，**解决它们之间的冲突**，输出"谁覆盖谁"的决策记录。

## 输入文件
- `raw/d5/memory_events_raw.jsonl` — 14 条记忆事件（含重复 event_id、缺失时间、错别字"祥细"）
- `raw/d5/user_memory_snapshots_raw.csv` — 12 行用户当前记忆快照
- `raw/d5/conflict_candidates_raw.txt` — 7 个用户的已知冲突清单

## 任务步骤
1. 抽 4 类事件：
   - `preference`（偏好）
   - `knowledge_update`（知识）
   - `temporary_instruction`（临时指令，`ttl=short`）
   - `forget`（遗忘指令）
2. 处理冲突，按这套规则：
   | 场景 | 处理 |
   |------|------|
   | 用户最新明确偏好 vs 旧偏好 | **覆盖**，旧版本进历史 |
   | 用户明确偏好 vs 系统默认 | 用户优先 |
   | 新知识 vs 旧知识 | 覆盖，保留覆盖证据 |
   | 临时指令（`ttl=short`） vs 长期偏好 | **不覆盖**长期 |
   | `forget` 事件 | 直接从长期记忆移除 |
   | 时间缺失 / 错别字 | 标 `needs_review` |
3. 合并同义说法（如"奇麟" → "麒麟"）
4. 输出 `merged_memories.jsonl`，每条带 `action: keep/override/remove/review` 和 `reason`
5. 输出 `conflict_report.md`：每个冲突列出原因、证据、建议动作

## 预期清理效果
- 最新偏好覆盖旧偏好，历史可追踪
- 临时指令不污染长期记忆
- "别记""忘记"的内容彻底不进检索
- 同义、错字、大小写不产生重复记忆
- 冲突项都能说出原因和证据

## 简单解释
> D5 是"审案子"——7 个用户都在"前后说法不一样"，要当法官判"哪个新、哪个旧、哪个临时、哪个要删"，还要把判决书写出来。
