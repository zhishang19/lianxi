# D4 多源清洗实战

## 一句话理解
把 **5 份不同来源** 的脏数据（对话、知识、偏好、配置、工具结果）整理成 4 类标准化 JSON + 1 份报告。

## 输入文件
| 文件 | 是什么 |
|------|--------|
| `raw/d4/chat_logs_raw.jsonl` | 16 行多轮对话（含口水词、HTML、纠错、隐私、临时指令） |
| `raw/d4/knowledge_raw.txt` | 6 个知识案例（含口水词、垃圾行、错别字、冲突新旧说法） |
| `raw/d4/preferences_raw.csv` | 12 条偏好记录（含版本号 v0/v1/v2、缺 uid、重复、临时例外） |
| `raw/d4/config_manual.yaml` | 管理员配置（含 TTL、默认偏好、敏感正则、遗忘指令列表） |
| `raw/d4/tool_result_raw.jsonl` | 8 条工具轨迹（含成功/失败/超时、日志噪声、重复 trace） |

## 任务步骤
1. **对话 → `chats.json`**：清洗、规整、按 `session` 分组
2. **知识 → `knowledge.json`**：解析 `=== 案例开始 ===` 段，丢弃垃圾行，补齐结构（标题/步骤/标签/注意）
3. **偏好 → `preferences.json`**：按 `uid + pref_key` 聚合，保留 `version` 链，临时指令打 `scope=short`
4. **工具结果 → `tools.json`**：保留 `status`、耗时、关键 `output`，去掉 HTML 注释和口水词，重复 trace 合并
5. 写 `report.md`，包含：
   - 发现的隐私字段（邮箱、手机号）
   - 发现的冲突项（U001 的简洁 vs 详细、U002 的 emoji 策略、U003 的驱动入口）
   - `needs_review` 列表（无法自动判断的项）

## 预期清理效果
- 对话简洁、可检索
- 偏好能区分"默认 / 明确表达 / 临时例外"
- 知识形成稳定结构
- 工具结果只剩关键字段
- 冲突、遗忘、敏感、错别字单独记录

## 简单解释
> D4 是"做收纳"——5 个抽屉（对话/知识/偏好/配置/工具）都乱，重新分类装进 4 个新抽屉，留个清单记下"哪些东西不知道该放哪"。
